# 03. Core Rules

이 문서는 한 판에서 실제로 작동하는 최소 규칙을 정의한다. 구현 전에는 이 규칙을 작은 범위로 유지하고, 프로토타입에서 재미가 확인된 뒤 확장한다.

## Board Model

첫 버전은 자유 이동 보드가 아니라 `슬롯 기반 세탁소`로 설계한다.

- `Order Row`: 상단에 손님 주문 표시
- `Work Area`: 중앙에 기계와 바구니 표시
- `Dream Queue`: 처리해야 할 꿈 조각 목록
- `Action Bar`: 하단에 되돌리기, 재시작, 힌트 표시

슬롯 기반을 우선하는 이유:

- 한 손 조작이 쉽다.
- 상태와 목표를 명확히 표시할 수 있다.
- 레벨 데이터와 검증기를 만들기 쉽다.
- 물리 기반보다 예측 가능한 퍼즐을 만들 수 있다.

## Core Entities

### Dream Fragment

꿈 조각은 하나의 상태 목록이 아니라 여러 `속성 축`을 가진다. 이렇게 나누면 레벨 데이터, 주문 비교, 자동 검증을 단순하게 만들 수 있다.

초기 프로토타입 필수 속성:

- `stain`: `None`, `Nightmare`
- `moisture`: `Dry`, `Wet`

후속 확장 속성:

- `color`: 색상
- `form`: `Flat`, `Folded`
- `damage`: `None`, `Torn`
- `emotion`: 감정

초기 주문과 기계는 `stain`과 `moisture`만 비교한다. 예를 들어 "깨끗하고 마른 꿈"은 `stain=None`, `moisture=Dry` 조건이다.

### Customer Order

손님 주문은 목표 속성 조건의 묶음이다. 주문은 필요한 속성만 지정할 수 있고, 지정하지 않은 속성은 비교하지 않는다.

예:

- `stain=None`, `moisture=Dry` 꿈 1개
- `stain=None` 꿈 2개
- `stain=Nightmare`, `moisture=Dry` 꿈 1개

주문은 반드시 아이콘으로 표현 가능해야 한다.

### Machine

기계는 꿈 조각의 속성을 바꾼다.

초기 프로토타입 필수 기계:

- `Washer`: `stain=Nightmare`를 `stain=None`으로 바꾸고, 항상 `moisture=Wet`으로 만든다.
- `Dryer`: `moisture=Wet`을 `moisture=Dry`로 바꾼다.

후속 확장 기계:

- `DyeVat`: `color` 변경
- `Folder`: `form=Folded` 부여
- `Mender`: `damage=Torn` 복구
- `WarmDryer`: 슬픔을 추억으로 변환

### Basket

바구니는 임시 보관 공간이다.

- 각 바구니는 정수 `capacity`를 가진다.
- 각 꿈 조각은 `capacityCost`만큼 capacity를 사용한다.
- 프로토타입의 모든 꿈 조각은 `capacityCost=1`이다.
- 프로토타입에서는 바구니 간 상태 제한을 두지 않는다.
- 이후 접기 규칙이 들어오면 `form=Flat`은 `capacityCost=2`, `form=Folded`는 `capacityCost=1`처럼 정수 비용으로 확장한다.
- 이후 젖은 꿈 전용, 색상 전용, 접힌 꿈 전용 같은 바구니 변형을 추가할 수 있다.

## Turn Model

첫 버전은 `턴 제한`을 기본으로 한다.

한 턴으로 계산하는 행동:

- 꿈 조각을 기계에 넣기
- 꿈 조각을 바구니로 이동
- 꿈 조각을 주문에 제출
- 기계에서 처리 완료된 꿈을 꺼내기

턴 제한을 쓰는 이유:

- 시간 압박보다 계획 퍼즐에 적합하다.
- 모바일 중단/재개에 강하다.
- 레벨 난이도 계산이 쉽다.

## Clear Conditions

레벨 클리어 조건:

- 모든 손님 주문이 정확히 충족된다.
- 제출되지 않은 필수 꿈 조각이 없다.
- 실패 상태의 꿈 조각이 없다.

## Failure Conditions

초기 버전 실패 조건:

- 제한 턴 초과
- 필수 꿈 조각을 되돌릴 수 없는 실패 상태로 만듦
- 모든 보관/기계 공간이 막혀 더 이상 이동할 수 없음

실패는 가능한 한 즉시 보여주되, 초반에는 되돌리기로 복구 가능하게 한다.

## Undo And Hint

### Undo

- 프로토타입: 1단계 또는 무제한 되돌리기
- 출시형: 기본 무제한 되돌리기 또는 소모형 힌트와 분리

퍼즐 학습 단계에서는 되돌리기가 재미를 해치지 않고 실험을 장려한다.

### Hint

힌트는 정답 전체를 보여주지 않는다.

- 다음 유효한 첫 수 제안
- 막힌 이유 표시
- 변환 결과 미리보기 강화

## Rule Boundaries

초기 구현에서 제외할 것:

- 실시간 타이머
- 랜덤 변환 결과
- 물리 기반 이동
- 너무 많은 감정 상태
- 손님별 긴 텍스트 조건

이 제외 항목은 프로토타입의 목표가 핵심 퍼즐 재미 검증이기 때문이다.
