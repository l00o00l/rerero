# 10. Prototype Success Criteria

프로토타입의 목표는 완성도 높은 게임을 만드는 것이 아니라, 핵심 재미 가설이 맞는지 검증하는 것이다.

## Prototype Goal

검증할 핵심 가설:

> 세탁기와 건조기, 제한된 바구니만으로도 꿈 조각을 변환하고 정리하는 퍼즐 재미가 생긴다.

## Prototype Scope

포함:

- 세로 화면
- capacity 기반 보관을 쓰는 슬롯형 세탁소
- 꿈 조각 3-4종
- 속성: `stain=None/Nightmare`, `moisture=Dry/Wet`
- 기계: `Washer`, `Dryer`
- 바구니 2개
- 손님 주문 1-3개
- 턴 제한
- 되돌리기
- 재시작
- 10개 수제 레벨

제외:

- 염색
- 접기
- 수선
- 감정 상태
- 메타 성장
- 이벤트
- 광고/수익화
- 자동 레벨 생성기
- 고급 아트

## Success Criteria

### Core Fun

성공 기준:

- 10개 레벨 중 6개 이상에서 공간/순서 고민이 생긴다.
- 플레이어가 세탁 -> 건조 -> 제출 체인을 자연스럽게 이해한다.
- 실패 후 재시도 의사가 생긴다.

실패 신호:

- 기계에 넣는 순서가 너무 뻔하다.
- 바구니 공간이 의미 없다.
- 꿈 상태 변환이 귀찮은 절차처럼 느껴진다.

### Rules

성공 기준:

- 모든 프로토타입 규칙을 10레벨 안에서 단계적으로 설명할 수 있다.
- 잘못된 제출과 막힌 상태의 이유가 명확하다.
- 되돌리기로 실험이 가능하다.

실패 신호:

- 유저가 왜 제출이 안 되는지 이해하지 못한다.
- 세탁 후 `moisture=Wet`이 붙는 것을 놓친다.
- 턴 제한이 불공정하게 느껴진다.

### UX

성공 기준:

- 한 손으로 모든 조작이 가능하다.
- 꿈 상태를 아이콘/색/형태로 구분할 수 있다.
- 주문과 현재 꿈 상태를 비교하기 쉽다.

실패 신호:

- 손가락이 중요한 정보를 가린다.
- 주문 카드가 너무 작다.
- 상태가 텍스트 설명 없이는 이해되지 않는다.

### Satisfaction

성공 기준:

- 세탁/건조 완료 피드백이 명확하다.
- 제출 성공이 기분 좋다.
- 재시작이 빠르다.

실패 신호:

- 애니메이션이 느리다.
- 반복 조작이 밋밋하다.
- 실패 연출이 과하게 부정적이다.

### Content Production

성공 기준:

- 10개 수제 레벨이 코드 수정 없이 데이터로 정의된다.
- 같은 규칙으로 추가 10개 레벨 초안을 만들 수 있다.
- 기본 규칙이 20레벨까지 확장 가능해 보인다.
- 레벨 데이터 구조가 염색/접기 확장을 막지 않는다.

실패 신호:

- 5레벨 이후 변형이 고갈된다.
- 레벨 제작에 코드 수정이 필요하다.
- 해답 가능성을 사람이 매번 손으로만 확인해야 한다.

## Prototype Test Plan

1. 내부 테스트
   - 10레벨 전체 플레이
   - 각 레벨 예상 해법 턴 수 기록
   - 막힌 상태 기록

2. 조작 테스트
   - 마우스
   - 터치 에뮬레이션
   - Android 에뮬레이터 또는 실제 기기

3. 관찰 항목
   - 첫 실수 지점
   - 주문을 읽는 시간
   - 재시도 여부
   - 가장 만족스러운 행동
   - 가장 헷갈린 상태

## Go / No-Go Decision

### Go

아래를 만족하면 다음 단계로 간다.

- 기본 규칙으로 10레벨이 성립한다.
- 공간 압박과 순서 계획이 느껴진다.
- 세탁/건조 피드백이 좋다.
- 추가 규칙 없이도 20레벨까지 확장 가능해 보인다.

### Iterate

아래면 기획을 조정한다.

- 재미는 있지만 상태 판독이 어렵다.
- 퍼즐은 되지만 손맛이 약하다.
- 레벨은 만들 수 있지만 난이도 곡선이 급하다.

### Stop Or Pivot

아래면 큰 방향 전환을 고려한다.

- 변환이 퍼즐이 아니라 작업처럼 느껴진다.
- 바구니/기계 capacity 제약이 재미를 만들지 못한다.
- 꿈 세탁소 컨셉이 규칙과 따로 논다.
