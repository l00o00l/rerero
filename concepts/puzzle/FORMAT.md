# Puzzle Concept Format

새 퍼즐 게임 컨셉 문서는 아래 포맷을 따른다.

## Title

게임의 임시 제목. 기억하기 쉬운 영어 이름을 우선 사용하고, 필요하면 한국어 부제를 붙인다.

## One Line Pitch

5초 안에 이해되는 한 문장 설명.

## Player Fantasy

플레이어가 어떤 역할을 하는지, 왜 그 상황이 매력적인지 쓴다.

## Core Loop

한 판의 반복 구조를 짧게 적는다.

1. 목표 확인
2. 제한된 조작으로 대상 이동/변환/정리
3. 조건 달성
4. 보상, 실패, 재시도

## One-Hand Control

세로 화면 한 손 조작을 어떻게 구현할지 적는다.

- 탭
- 드래그
- 스와이프
- 홀드
- 되돌리기

## Puzzle Rules

컨셉을 구성하는 최소 규칙 단위를 나열한다. 레벨을 많이 만들려면 규칙이 서로 조합 가능해야 한다.

## Level Production Model

많은 레벨을 만들기 위한 파라미터를 적는다.

- 목표 수
- 대상 수
- 보드 크기
- 보관 공간
- 제한 턴/시간
- 특수 오브젝트
- 실패 조건

## Difficulty Curve

초반, 중반, 후반에 어떤 규칙을 열지 적는다.

## Event And LiveOps Fit

시즌 이벤트, 일일 퍼즐, 스킨, 테마 교체가 어떻게 붙는지 적는다.

## Prototype Scope

첫 Unity 프로토타입에서 반드시 검증할 최소 범위를 적는다.

## Release Potential

출시 가능성을 높이는 요소와 약점을 함께 적는다.

## Risks

구현, 레벨 제작, UX, 수익화, 차별화 리스크를 기록한다.
